## 2026-11-08 — 手順 5: 登録した架台との位置合わせと、グリッド・パネルの自動の割り当て（ブランチ `layout-align`）

- 解析エンジンに `align-layout`: 架台を撮影情報で画像に重ね、画像の架台の辺（上端・下端・始まり・終わり）との対応から補正（平行移動・拡大縮小・小さな回転）を外れ値を除いて求め、残差をパネル幅に対する割合で出す。閾値（`config/layout_overlay.yml` の 0.25）以内で、架台の端と長辺の両方の手がかりがあれば aligned、それ以外（架台が写っていない・端が写っていない・残差が大きい・対応がそろわない）は needs_review（理由付き）
- Rails: 架台を登録した発電所の、位置合わせに使える画像は品質チェックの後に `AlignLayoutJob` へ。自動ならグリッド（架台の ID 付き）を保存して解析へ、できなければ `alignment_failed`（要確認）にして下書きのグリッドを残す。`inspection_images.alignment`（状態・残差・補正量・設定の版）を追加し、点検画面に表示
- 異常のパネルの割り当て（設計原則 9 の「位置情報による割り当て」）: 位置合わせのグリッドの異常は、行・列から架台のパネルに割り当て、根拠を `panel_assignment_history` に残す。人が下書きを直して保存したグリッドも架台の ID を残して割り当てる（`layout_adjusted`）。架台の ID の無いグリッドは今までどおり人が割り当てる
- グリッドの画面: 位置合わせできなかった画像では、下書き（架台を重ねたもの）を表示する
- レビュー画面: 位置合わせのグリッドがある画像では、パネルの選択肢を写っている架台のパネルに絞る。重複のまとめ先の候補は同じパネル → 同じ架台の順に 50 件まで（架台から作ったパネルが数千枚あると画面が重くなったため）

- 判断した事項: 位置合わせに使えない画像では、グリッドの自動提案（propose-grid）は作らない（架台を登録した発電所では使わないため）。レビュー画面のパネルの選択肢を絞ったのは指示に無い変更（画面が使えないほど重くなったため。全パネルから選べる必要があれば戻す）
